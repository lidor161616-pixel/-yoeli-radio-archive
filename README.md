# DIKMAN FM – אפליקציית רדיו (PWA)

> שם התחנה: DIKMAN FM. מופיע ב-`js/config.js`, ב-`index.html` וב-`manifest.webmanifest`.

**ההחלטות המרכזיות, ולמה:**

| החלטה | הסיבה |
|---|---|
| **PWA ב-JavaScript רגיל, בלי React ובלי שלב בנייה** | נטען מהר גם על טלפון ישן או חלש, רץ גם בדפדפנים ישנים (Android WebView 60+, iOS 12+) ואין מה "לשבור" בעדכונים. |
| **המאזין אף פעם לא פונה לטלגרם** | רוב ספקי הסינון חוסמים את טלגרם. GitHub מוריד את הקבצים ל-R2, והמאזינים שומעים משם. |
| **בלי שרת לתחזק** | GitHub מריץ את הסנכרון ומארח את האתר, Cloudflare מאחסן את הקבצים. אין מה לעדכן או לגבות. |
| **כל הקבצים מהדומיין שלכם** | סינונים חוסמים לעיתים CDN-ים חיצוניים. לפני עלייה לאוויר מעבירים את הפונטים לתיקיית `fonts/` מקומית (כרגע הם נטענים מ-Google Fonts). |
| **שידור חי ב-MP3/AAC מ-Icecast** | מתנגן בתגית `<audio>` בכל מכשיר. HLS (`.m3u8`) עובד באייפון, אבל באנדרואיד ישן הוא צריך ספרייה נוספת. |
| **Media Session API** | שליטה ממסך הנעילה, מאוזניות ומהרכב, ונגינה ברקע. |
| **מצב שבת וחג מובנה** | מכניסת השבת ועד צאתה (לפי שקיעה מחושבת) ההשמעה ננעלת ומוצג מסך "שבת שלום". ימים טובים מגדירים ב-`config.js`. |
| **ניווט במקשים** | לטלפונים כשרים עם מקלדת או "חצי טאץ'": 5 לנגן/לעצור, 4/6 לדילוג של 15 שניות, 2/8 לפריט הקודם/הבא, וחיצי מעלה/מטה לתנועה בין הכפתורים. |

## 1א. איך הרדיו עובד (לוח שידורים)

- **ברירת מחדל:** שידורים חוזרים מהארכיון ברצף, בסדר אקראי וללא חזרות עד שכל ההקלטות התנגנו.
- **בשעות השידור החי** (מוגדרות ב-`schedule` ב-`config.js`, לפי שעון ישראל) הנגן עובר אוטומטית לשידור החי, ובסיומו חוזר לשידורים החוזרים.
- אם השידור החי לא עולה, ממשיכים בשידורים חוזרים ומנסים שוב כל 2 דקות.
- מאזין שבחר הקלטה מהארכיון באמצע שידור חי, ממשיך לשמוע אותה. בסיומה הנגן חוזר לשידור החי.
- דפדפנים לא מתחילים לנגן בלי לחיצה, ולכן ההאזנה מתחילה בלחיצה הראשונה של המאזין. מכאן והלאה כל המעברים אוטומטיים.
- תצוגה של מצב "חי" בכל שעה: להוסיף `#live-preview` לסוף הכתובת.

## 4. הקמה: ארכיון אוטומטי מטלגרם (פעם אחת, כ-30 דקות, הכול בדפדפן)

| ערוץ | קטגוריה |
|---|---|
| @Masster_Play | מאסטר פליי |
| @laila_menatzeach | לילה מנצח |

### א. בוט בטלגרם
1. ‏‎@BotFather ← `/newbot` ← שם ← שם משתמש שמסתיים ב-`bot`. שומרים את **הטוקן**.
2. מוסיפים את הבוט **כמנהל** בשני הערוצים.
3. ב-https://my.telegram.org ← **API development tools**: שומרים את **api_id** ואת **api_hash**.

### ב. אחסון ב-Cloudflare R2
1. נרשמים ב-https://dash.cloudflare.com ← בתפריט **R2 Object Storage**. כדי להפעיל R2 צריך להוסיף אמצעי תשלום. 10GB ראשונים חינם, ומעבר לזה בערך $1.5 לכל 100GB בחודש. תעבורה להאזנה חינמית.
2. **Create bucket**, למשל בשם `yoli-archive`.
3. ב-bucket: ‏**Settings ← Public access ← R2.dev subdomain ← Allow**. מעתיקים את הכתובת (`https://pub-….r2.dev`).
4. בעמוד R2 הראשי: מעתיקים את ה-**Account ID**. אחר כך **Manage API tokens ← Create API token**, בוחרים **Object Read & Write** רק ל-bucket הזה, ומעתיקים את **Access Key ID** ואת **Secret Access Key**.

### ג. GitHub (מריץ ומארח)
1. נרשמים ב-https://github.com ← **New repository**, למשל `yoli-radio`, ובוחרים **Public**. במאגר ציבורי ההרצות חינמיות. הסודות עצמם לא נחשפים.
2. **uploading an existing file** ← גוררים את **כל התוכן** של התיקייה `radio-app` (כולל התיקייה `.github`) ← Commit.
   במק התיקייה `.github` מוסתרת ב-Finder. מציגים אותה עם Cmd+Shift+נקודה.
3. **Settings ← Secrets and variables ← Actions**:
   - בלשונית **Secrets**, ‏(New repository secret) לכל אחד:
     `TG_API_ID`, `TG_API_HASH`, `TG_BOT_TOKEN`, `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET` (שם ה-bucket)
   - בלשונית **Variables**: ‏`MEDIA_BASE_URL` = הכתובת `https://pub-….r2.dev`
4. **Settings ← Pages ← Source: GitHub Actions**.
5. **Actions** ← מאשרים הפעלה ← **ארכיון ואתר** ← **Run workflow**.

אחרי כמה דקות האתר באוויר בכתובת `https://<שם-המשתמש>.github.io/yoli-radio/`.

### מה קורה מכאן
- **ההיסטוריה המלאה** נמשכת אוטומטית בכמה הרצות ברצף. כל הרצה עובדת עד כ-5.5 שעות, והבאה ממשיכה מאותה נקודה. אין צורך לעשות כלום. ההתקדמות נראית בלשונית Actions.
- **פרקים חדשים** נכנסים לארכיון עד שעה אחרי שעלו לטלגרם.
- **כותרת ותאריך:** השורה הראשונה בכיתוב הפוסט היא הכותרת. התאריך נלקח מהכותרת (12.11.26), ואם אין בה תאריך, נלקח תאריך הפוסט.
- **חיסכון באחסון (אופציונלי):** ב-Variables מוסיפים `AUDIO_BITRATE` = `96k`, והקבצים יידחסו ל-MP3 של 96kbps לפני ההעלאה.
- **עריכה ומחיקה:** פוסט שנמחק או נערך בטלגרם לא מתעדכן אוטומטית. מתקנים את `data/episodes.json` ישירות ב-GitHub (עיפרון ← Commit).
- ב-GitHub, ריצות מתוזמנות במאגר ציבורי נעצרות אחרי 60 יום בלי שום שינוי במאגר. כל פרק חדש מעדכן את המאגר, כך שכל עוד עולים פרקים זה לא יקרה.

### דומיין משלכם (מומלץ בגלל הסינונים)
כתובות `github.io` ו-`r2.dev` עלולות להיחסם בחלק מהסינונים. עם דומיין משלכם: ב-**Settings ← Pages ← Custom domain** לאתר, וב-R2 ‏**Settings ← Custom Domains** לקבצים, למשל `media.הדומיין`. אחר כך מעדכנים את `MEDIA_BASE_URL`. אז מבקשים מספקי הסינון לאשר את שני הדומיינים.

## 5. שידור חי

ב-`js/config.js` מחליפים את כתובות `stream.example.com` בכתובות השידור האמיתיות, ומעבירים את `demo` ל-`false`.
- כתובות **HTTPS** בלבד (אחרת הדפדפן חוסם אותן באתר מאובטח).
- "מתנגן עכשיו": בשדה `nowPlaying` שמים את כתובת `status-json.xsl` של Icecast.
- מדי VU אמיתיים: מפעילים בשרת השידור כותרת `Access-Control-Allow-Origin` ומגדירים `realMeters: true`. בלי הכותרת הזו המחוגים זזים בתנועה מדומה, כי חיבור לנתוני השמע בלי CORS משתיק את השידור.

## 6. התאמה למכשירים

| מכשיר | מצב |
|---|---|
| אנדרואיד (סמסונג וכו') | התקנה כאפליקציה בכפתור "התקנה" או מתפריט Chrome, ונגינה ברקע. |
| אייפון | "שיתוף ← הוספה למסך הבית". את העוצמה שולטים רק מכפתורי המכשיר, ולכן הפיידר מוסתר אוטומטית. |
| טלפונים כשרים/מסוננים עם דפדפן | צריך לבקש מספקי הסינון לאשר את הדומיין של האתר ושל שרת השידור. |
| טלפונים כשרים בלי דפדפן | צריך אפליקציה ארוזה (APK) לחנויות הכשרות, ראו שלב הבא. |
| טלפון כשר רגיל (בלי מסך מגע) | אפשר להוסיף קו טלפוני (IVR) שמשמיע את אותו שידור. |

## 7. שלבים הבאים

1. העברת הפונטים לקבצים מקומיים ובדיקה מול ספקי הסינון.
2. אריזה כ-APK עם **Capacitor** (אותו קוד בדיוק) להפצה בחנויות הכשרות. מאותה עטיפה אפשר להגיש גם ל-App Store.
3. קו טלפוני שמשדר את אותו stream.
4. התראות על תוכנית חדשה (Web Push באנדרואיד, ובאייפון רק אחרי התקנה למסך הבית).
5. מסך ניהול קטן לעריכת כותרות וקטגוריות בלי לגעת ב-JSON.
